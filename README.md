# Наш остров

> **🇷🇺 Российская копия.** Это копия приложения, рассчитанная на работу из России
> **без VPN**: бэкенд — не облачный Supabase.com, а **свой собственный Supabase на
> российском сервере** (Timeweb Cloud). Код приложения идентичен оригиналу; отличается
> только адрес сервера в `.env`. Пошаговая настройка сервера и переноса данных —
> в [docs/RUSSIAN-HOSTING-SETUP.md](docs/RUSSIAN-HOSTING-SETUP.md).

Реальная версия прототипа: React + Vite + Three.js на фронтенде, Supabase вместо
`window.storage` на бэкенде (Postgres + Realtime + Storage для фото).

## Что изменилось по сравнению с прототипом

| Было (прототип в Claude) | Стало (это приложение) |
|---|---|
| `window.storage` — работает только внутри артефактов Claude | Supabase: настоящая база данных, доступна с любого хостинга |
| Опрос каждые 4 секунды (polling) | Supabase Realtime — партнёр видит новое событие мгновенно |
| Фото как base64-строка внутри JSON | Фото как файл в Supabase Storage, в базе хранится только ссылка |
| Один HTML-файл | Обычный React-проект, как РусНеКусь и МатНеСтрашь |

Вся 3D-геометрия (дом, горы, лес, озеро, город, веха и остальные 10 локаций)
перенесена без изменений — она уже была на чистом Three.js, так что просто
переехала в `src/scene/tileBuilders.js`.

## 1. Настройка Supabase (один раз)

1. Зайдите на [supabase.com](https://supabase.com) → создайте новый проект (бесплатный тариф достаточен).
2. **SQL Editor** → **New query** → вставьте содержимое `supabase/schema.sql` → **Run**.
3. **Storage** → **New bucket** → имя `event-photos` → включите **Public bucket** → создать.
4. Там же, в **Policies** для `event-photos`, добавьте две политики (текст — в конце
   `supabase/schema.sql` закомментирован, скопируйте оттуда):
   - разрешить `insert` для `anon`
   - разрешить `select` для `anon`
5. **Project Settings → API** — скопируйте `Project URL` и `anon public` ключ.

> Модель безопасности: код мира (6 символов) — это и есть общий секрет, как и в
> прототипе. Знание кода даёт доступ на чтение/запись. Для приложения на двоих
> по прямой ссылке этого достаточно. Если позже добавите вход по email/паролю —
> политики в `schema.sql` стоит ужесточить под конкретного пользователя.

## 2. Локальный запуск

```bash
npm install
cp .env.example .env
# впишите в .env свои VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY
npm run dev
```

Откройте адрес, который выведет Vite (обычно `http://localhost:5173`).

## 3. Деплой на Vercel (как РусНеКусь и МатНеСтрашь)

1. Запушьте проект в GitHub-репозиторий.
2. На [vercel.com](https://vercel.com) → **New Project** → выберите репозиторий.
3. Vercel сам определит, что это Vite-проект.
4. **Environment Variables** — добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`
   (те же значения, что в `.env`).
5. **Deploy**.

## 4. «Похоже на приложение» на телефоне без App Store

В `index.html` уже подключён `manifest.json` (PWA). На iPhone: Safari → Поделиться →
«На экран «Домой»». На Android: Chrome сам предложит «Установить приложение».
Значок появится на экране, откроется без адресной строки — ощущается как
нативное приложение, хотя это по-прежнему веб-сайт. Для полноценного офлайн-режима
позже можно добавить service worker (`vite-plugin-pwa`), но для MVP это не обязательно.

## Структура проекта

```
src/
  App.jsx                 — экран-роутер: онбординг → остров
  components/
    Onboarding.jsx        — создать/войти в мир
    AddEventModal.jsx     — выбор типа события + фото + заметка
    DetailPanel.jsx       — карточка при клике на локацию
  scene/
    IslandScene.jsx       — жизненный цикл Three.js-сцены внутри React
    tileBuilders.js       — вся геометрия локаций (15 типов) + текстуры
    hexMath.js            — гексагональная сетка и спираль размещения
  lib/
    supabaseClient.js     — инициализация клиента
    worldStore.js         — вся работа с базой: создание мира, события, фото, realtime
supabase/
  schema.sql              — таблицы, политики безопасности, инструкция по Storage
```

## Дальнейшие шаги, если понадобятся

- **Настоящая авторизация** — Supabase Auth (email-ссылка или телефон) вместо
  голого кода мира, если захочется больше приватности.
- **Push-уведомления** партнёру о новом событии — понадобится либо нативная
  обёртка (Capacitor), либо Web Push.
- **Native-приложение** — тот же React-код можно обернуть в Capacitor и
  собрать в App Store / Google Play без переписывания логики.
